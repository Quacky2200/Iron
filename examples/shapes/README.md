# shapes

A single-file gallery of Iron's 2D drawing: ten shapes laid out in two rows, each a `LineRenderer2D` (outline, fill, or
both) with points generated by the `Shapes` helpers, and each labelled with a `TextMesh`. It shows the two polygon fill
rules side by side and an animated shape whose outline and fill follow its object's rotation.

APIs used: `GameObject`, `Component`, `register`, `Camera` (orthographic), `LineRenderer2D` (`points`, `width`, `color`,
`loop`, `fillColor`, `fillRule`), `TextMesh` (`text`, `fontSize`, `fontWeight`, `color`, `maxWidth`), `Shapes.rectangle`,
`roundedRectangle`, `circle`, `pie`, `arc`, `bezier`, `closedCurve`, `regularPolygon`, and `Vector2/Vector3/Color`.

## Build and run

```bash
cd tools && cargo run -q -p iron_build -- build ../examples/shapes
```

then from the repo root:

```bash
cargo run -p iron_app -- examples/shapes
```

A single file can also be packaged with `iron-build package ../examples/shapes`. A screenshot run is
`cargo run -p iron_app -- examples/shapes --screenshot out.png --frames N` (for example `--frames 30`). The interactive
window may crash some GPUs; the screenshot run is the safest check.

## How it works

`register({ Gallery, Spin })` at the bottom registers both classes. Per `docs/scripting.md`, the host makes one GameObject per
registered class that is not registered with `spawn: false`, holding that component, so `Gallery` starts on its own and its
`onAwake` builds the whole scene. (`Spin` also gets such a spawned object, which is harmless; the hexagon gets its own `Spin`
through `addComponent`. Pass `{ spawn: false }` for classes meant only to be added by code.)

Setup is in `Gallery.onAwake`: an orthographic camera 10 units tall.

```ts
new GameObject("Main Camera", { position: new Vector3(0, 0, 10) }).addComponent(Camera, {
  orthographic: true,
  orthographicSize: 5,
  backgroundColor: Color.hex("#141922"),
});
```

Every shape goes through one helper that makes a `GameObject`, adds a `LineRenderer2D`, applies a small `Look` interface
(width, loop, fill colour, fill rule) and puts a `TextMesh` label 1.25 units below:

```ts
const go = new GameObject(name, { position: at });
const line = go.addComponent(LineRenderer2D);
line.points = points;
line.width = look.width !== undefined ? look.width : 0.06;
line.color = ink;
line.loop = look.loop !== undefined ? look.loop : true;
```

The shapes: `rectangle`, `roundedRectangle`, `circle` (semi-transparent red fill, alpha 0.6), `pie`, `arc` (open, `loop: false`),
two stars, a `bezier` (open), a `closedCurve` and a `regularPolygon`. The star is one self-crossing stroke, so the fill rule
decides whether its centre is filled:

```ts
shape("star, even-odd", new Vector3(-6, row2, 0), star(0.95), { fillColor: Color.hex("#7a5af0") });
shape("star, non-zero", new Vector3(-3, row2, 0), star(0.95), { fillColor: Color.hex("#7a5af0"), fillRule: "nonzero" });
```

Without `fillRule` the default is used (the label says even-odd). The last shape gets a `Spin` component, which rotates the
object each frame so you can see the outline and tessellated fill turn together:

```ts
class Spin extends Component {
  override onUpdate(dt: number): void {
    this.transform.rotate(new Vector3(0, 0, 40 * dt));
  }
}
```

A footnote `TextMesh` with `maxWidth: 900` wraps a longer sentence: "Outlines are capsules drawn by Rust; fills are tessellated
when the points change."

## Controls

None. The scene is static apart from the spinning hexagon.

## Things to try and gotchas

- Change `fillRule` or the star's point order to see how the rules differ; try `Shapes.pie` with other angles.
- Build a tiny vector-art or diagram tool: make points from your own data and assign `line.points` each frame (the fill is
  re-tessellated whenever points change, so avoid doing that every frame for big shapes unless you need to).
- Use `LineRenderer2D` for debug overlays or HUD-in-world: it is cheap to create one per shape.
- Add `sortingOrder` (not used here; `clock` and `splines` use it) to control which shape draws over which.
- Parent shapes to one root and animate the root, as `clock` does with its faces.
- Style notes: the code avoids `a ?? b` and optional properties are checked with `!== undefined`; the source uses that pattern
  throughout (a style of the compiled-TypeScript subset, not necessarily a requirement).
- Colours are `Color.hex(...)` or `new Color(r, g, b, a)` with 0..1 channels.

Related examples: splines, clock, sine-circle-demo, raindrop-demo
