# Every declaration generated from Rust

Status: written 2026-10-22; **phases P0 and P1 are built** (see "Progress" at the end), the rest is the plan.

**The rule (from the user):** no hand-written `.d.ts` anywhere. Everything `tsc` sees for an Iron game is **generated**:
from the `#[iron_api]` manifests (`crates/iron_api_macros` -> `Namespace::to_json` -> `tools/iron_ts/src/manifest.rs` and
`tools/iron_ts/src/types_dts.rs` -> `types/iron.d.ts`, written by `iron-build types` and by every `iron-build build` into
`dist/.tsc/iron.d.ts`), plus **compiler-owned tables in Rust** for the names that cannot be Rust classes (`setTimeout`,
`register`, `@property`, the React hooks, ...). Engine logic has **one native Rust implementation** that QuickJS and compiled
code both call: no TypeScript copy in `tools/iron_ts/src/lower/facade.ts` and another in `js/engine/src`.

**Where the rule is broken today** (all under `tools/iron_ts/src/lower/`):

| File | Lines | What it is | How it gets to `tsc` / the game |
|---|---|---|---|
| `engine_ts.d.ts` | 609 | 95 hand-written top-level declarations and 3 `//@ctor` lines | `include_str!` in `types_dts.rs` (`ENGINE_TS_DTS`), appended to `iron.d.ts`; its member names hide the generated ones of the same name (`parse_supplement`) |
| `facade.ts` | 1434 | 50 `//# when` chunks of TypeScript with real logic, compiled into a game that names a trigger | `include_str!` in `facade.rs` (`FACADE_TS`), appended to the program by `extend_source` |
| `ambient.d.ts` | 636 | 45 declarations: `IronStyle` and its unions, events, `ReactNode`, `JSX`, hooks, `console`, `createRoot`, `Text`.., `Gamepad`, `Collision` | `include_str!` (`AMBIENT_DTS`), appended verbatim. Said to be generated by `scripts/gen_ambient.py` (311 lines of Python reading `js/react/src/style.ts`), but it was **edited by hand since** (SVG attributes, `clipPath`, `createRoot(target?: WorldPanel \| Window \| number)`; TODO.md "Engine names as globals" item 7) |
| `ambient.ts`, `ui.ts` | 81 + 175 | The compiled side of the same names: `StyleValue`, `StyleEntry`, `UiEvent` with hard-coded slot numbers (`clientX = Ui.evNum(0)` ...) | compiler prelude (also written by `gen_ambient.py`) |
| `ui_manifest.json`, `ui_root_manifest.json` | 1 + 1 | The `Ui` / `UiRoot` intrinsic namespaces | **already generated** from Rust (`iron_ts_ui::manifest_json()`, guarded by `iron_ts_ui/tests/embedded_manifest.rs`); not visible to `tsc`. Fine as is |

Drift that already exists because of the hand-written copies (found while writing this):

- `Gamepad` in `ambient.d.ts` has `buttons` / `axes: Record<string, number>`; the compiled `Gamepad` (facade chunk `input.gamepads()`) has only
  `id`, `name`, `connected`. `tsc` accepts a game the compiler then rejects.
- `TangentMode` is `"auto" | "bezier" | "linear"` for `tsc` but `string` in the compiled `Spline` (a compiler panic, docs/iron-api.md).
- `FullScreenMode` is declared in `ambient.d.ts` **and** in a facade chunk; `Resolution`, `LodLevel`, `ClothBox`, `BloomSettings`,
  `HeightFogSettings`, ... are declared once in `engine_ts.d.ts` for `tsc` and again in `facade.ts` for the compiler (with `string`
  where `tsc` sees literal unions: `VolumetricFogSettings.resolution`, `AutoExposureSettings.metering`).
- `Shapes`, `Spline`, `SplineAnimate`, `Camera.screenToWorldPoint`, `Light.illuminanceAt` exist twice: `facade.ts` (compiled games)
  and `js/engine/src/{shapes,spline,rendering}.ts` (QuickJS games). The js/engine `SplineAnimate` saves its fields with `@property`;
  the facade one does not (TODO.md: "Facade chunk classes are not `@property` aware").
- The manifests' JSON has **no doc comments** (`function_json` in `crates/iron_api/src/lib.rs` drops `doc`, although `Function::doc`
  exists and `Namespace::to_dts` prints it), so every documented declaration today is a hand-written one.

## 0. Legend: the extensions this plan adds

The inventory refers to these. Each is a feature of `#[iron_api]` (macro + `iron_api::Ty` + manifest JSON + `manifest.rs` +
`types_dts.rs` + the QuickJS binding), a compiler built-in table, or a UI table. **Section 2** says how each works.

| Code | Extension | Rust side (example) | d.ts it generates |
|---|---|---|---|
| **F-DOC** | Doc comments in the manifest JSON (functions, params, classes, enums, records, fields) | `/// The disc's size in degrees.` | `/** .. */` |
| **F-ENUM** | String-literal enums | `#[iron_enum] pub enum FogMode { Linear, Exponential, ExponentialSquared }` | `type FogMode = "linear" \| "exponential" \| "exponentialSquared";` |
| **F-REC** | Plain-object records (mixed field types, optional fields, nested records/lists) as params, results and properties | `#[iron_record] pub struct HeightFogSettings { density: f64, base_height: f64, falloff: f64 }` | `interface HeightFogSettings { density: number; .. }` |
| **F-NULL** | `Option<T>` for handles, values, records, strings, numbers | `fn main() -> Option<CameraRef>` | `Camera \| undefined` / `T \| null` (`#[ts(undefined)]` picks which) |
| **F-LIST** | `Vec<T>` results and `&[T]` params / list properties for every kind (values, handles, strings, enums, records, tuples); `#[rest]` for variadic | `fn circle(c: V2, r: f64, segments: f64) -> Vec<V2>` | `Vector2[]`, `...points: Vector2[]` |
| **F-UNION** | Several setters / statics / methods / constructors under one script name, picked by argument type; the d.ts property type is the union | `#[setter(start_lifetime)] fn set_start_lifetime_range(self, v: &[f64])` next to the `f64` setter | `startLifetime: number \| number[]` |
| **F-CTOR** | `#[constructor]` statics (positional and options forms) and `#[options(after = p)]` | `#[constructor] #[optional(..)] fn new_positional(color: Rgba, ..)` | `constructor(color?: Color, ..)` (replaces `//@ctor`) |
| **F-SUB** | Subscriptions that return an unsubscribe function | `#[subscription(off = "off_change")] fn on_change(f: Callback<()>) -> u32` | `onChange(fn: () => void): () => void` |
| **F-PROMISE** | `Pending<T>` results: Rust resolves or rejects later | `fn load(path: &str) -> Pending<PrefabRef>` | `Promise<Prefab>` |
| **F-CBRET** | Callbacks with a result and record / handle / reply-closure arguments | `Callback<(HandleArg<WindowRef>, Json<T>), Json<R>>` | `(from: Window, data: T) => R` |
| **F-JSON** | Generic structured payloads: `Json<T>` with `#[generic(T)]`; the compiler checks the static type (`check_message_types`) and stringifies / parses it | `fn post_message(self, data: Json<T>) -> bool` | `postMessage<T>(data: T): boolean` |
| **F-EXT** | `extends` between handle classes (`BoxCollider extends Collider`, `SplineAnimate extends Component`), abstract handle classes | `#[iron_api(.., extends(SplineAnimate = Component))]` | `declare class SplineAnimate extends Component` |
| **F-ALIAS** | Another script name for a class, enum or global | `#[js_alias = "AnimatorController"]` | `type AnimatorController = AnimationController; declare const AnimatorController: typeof AnimationController;` |
| **F-GLOBAL** | A namespace function that is also a global | `#[global] fn load_font(face: FontFace)` | `declare function loadFont(face: FontFace): void;` |
| **F-TS** | Escape hatch: the TypeScript text of one param / result / field, written **on the Rust item** (`#[ts(type = "..")]`). Validated by the `tsc` test. Used where no structured form pays off (`NumberList`) | `#[ts(type = "NumberList")] positions: Floats` | as written |
| **B** | A **compiler built-in table** in Rust (`tools/iron_ts/src/builtins.rs`): name, typed signature, doc, and the lowering that implements it | `Builtin::func("setTimeout").param("fn", ts::closure(&[], VOID)).opt("ms", NUM).ret(NUM)` | `declare function setTimeout(..)` |
| **UI** | **UI tables** in Rust (`iron_ui` styles / attributes / elements, `iron_ts_ui` event fields) that both the implementation and the generator read | `StyleProp { name: "display", ty: Enum(&["flex", ..]), doc, group }` | `interface IronStyle { display?: .. }` |

Generated without a new feature (the generator alone): `Vector2Like` / `Vector3Like` / `QuaternionLike` (one `type <V>Like` per value
class, from its fields), the `@iron/engine` / `@iron/react` / `react` re-export modules (from the tables' module tags instead of the
three hard-coded `&[&str]` lists in `types_dts.rs`).

## 2. Mechanism

### 2.1 The pipeline after the change

```
Rust items (#[iron_api], #[iron_enum], #[iron_record], gen_components data)  --macro-->  iron_api::Namespace (static data)
       |                                                                                  |
       |                                                                       Namespace::to_json (manifest v2)
       |                                                                                  v
       |                                     tools/iron_ts/src/manifest.rs (ExtTy, records, enums, promises ...)
       |                                                                                  |
iron_ui / iron_ts_ui UI tables ----------------------------> tools/iron_ts/src/types_dts.rs  <---- tools/iron_ts/src/builtins.rs
                                                                                  |
                                                                       types/iron.d.ts (and dist/.tsc/iron.d.ts)
```

`types_dts::generate(manifests, ambient, supplement)` becomes `generate(manifests, &builtins::ALL, &ui_tables)`; the `include_str!` of
`ambient.d.ts` and `engine_ts.d.ts`, `parse_supplement` and its member-hiding rule are deleted at the end.

### 2.2 Manifest v2 (JSON written by `Namespace::to_json`, read by `manifest.rs` and `types_dts.rs`)

Additive, so old readers keep working while the phases land; `"version": 2` at the top.

- `doc` on functions, params, classes, values, enums, records and fields (**F-DOC**). The macro already collects `doc_of(attrs)`; only
  `function_json` drops it. `types_dts.rs` writes JSDoc (`jsdoc()` exists in `iron_api`).
- New type strings, parsed by `manifest.rs::ext_ty`:
  - `enum:FogMode` -> `ExtTy::Str` for the compiler (strings stay the wire form; question 6), the literal union for `tsc`.
  - `record:HeightFogSettings` -> a new `ExtTy::Record(name)`; `opt:<T>` -> `ExtTy::Opt(Box<T>)` (**F-NULL**).
  - `list:<T>` for results and params of any element kind (generalises `values:` / `handles:` / `f64s`); `tuple(f64,f64)`.
  - `promise:<T>` (**F-PROMISE**), `json:<G>` with a generic name (**F-JSON**), `fn(..):<R>` with a result (**F-CBRET**).
- `enums: [{ name, doc, aliases, values: [{ ts: "exponentialSquared", doc }] }]`.
- `records: [{ name, doc, fields: [{ name, type, optional, doc }] }]`.
- per class: `extends`, `abstract`, `aliases`, `ctors: [[params..]]`; per function: `generics: ["T"]`, `subscription: { off: "offChange" }`,
  `global: true`, `optionsName: "WindowOptions"`, `optionsAfter: 1`, `rest: true` on the last param, `ts` overrides (**F-TS**).

Overload sets (**F-UNION**) need no new field: several entries of one script name already make `manifest.overloads` for namespace
functions; the change is to allow them for class methods, setters and constructors too, and to make the generator print a property's
type as the union of its setters' types.

### 2.3 What each extension needs

| Code | Macro (`iron_api_macros`) | Compiled side (`iron_ts`) | QuickJS side (`iron_api::qjs`) | Generator |

### 2.4 The compiler built-in table (`tools/iron_ts/src/builtins.rs`, Rust data)

For names implemented by the compiler, not the engine: timers, `console`, `Component` and its hooks, `register`, `property`,
`ComponentClass` / `ClassOf`, the generic `GameObject` component members, `findObjectOfType`, `Random.pick`, the React hooks,

```rust
pub struct Builtin {
    pub name: &'static str,
    pub module: Module,            // Global, Engine, React, IronReact: drives the re-export modules
    pub doc: &'static str,
    pub decl: Decl,                // typed: Func { generics, params, ret } | Interface | TypeAlias | Namespace | Class
    pub lowering: Lowering,        // which compiler code implements it (enum tag; a test checks each is used)
}
```

Types are written with a small typed builder over a `TsType` enum (`Num`, `Str`, `Bool`, `Void`, `Unknown`, `Named`, `Lit`, `Generic`,

phantom type): allow **F-TS** text inside the table entry for them (question 1).

list per hook, so the compiler's hook thunks and the d.ts read one table. The contact hooks (`onCollisionEnter(c: Collision)` ...) can then
be declared too (TODO.md "Engine names as globals" item 5 notes they are missing).

### 3.3 What is genuinely compile-time (stays in the compiler, as Rust)

- **Typed messages** (`postMessage<T>`, `onMessage<T>`, `onRequest`, `request<R>`, `emit`, `on`, `ask<R>`, `answer`, `broadcast`,
  `emitAll`): the only compile-time part is "stringify / parse the static type `T`" and "one promise class per reply type `R`". With
  **F-JSON** the native API takes and gives JSON text; the lowerer inserts `JSON.stringify(x)` / `JSON.parse<T>(s)` around the call and
  the callback, checks `T` (`check_message_types` exists), and instantiates the promise for `R` (one Rust function instead of
  `REQUEST_TEMPLATE` / `ASK_TEMPLATE`). The reply table `__win_pending` moves into `iron_engine_api::window` (Rust keeps pending
  requests per id and settles the `Pending<Json<R>>`). The `on0` / `answer0` / `P` variants become one rule each: "a handler with no
  parameters gets no payload", "a handler returning a promise replies when it settles".
- **Generic component members** (`addComponent<T>(cls, props?: Partial<T>)`, `getComponent<T>`, `getComponents<T>`,
  `getComponentInChildren<T>`, `findObjectOfType<T>`): they mix user classes and engine handle classes; `arrays.rs` /
  `engine_objs.rs` keep lowering them; only their declarations move to **B**.
- **Object literals into engine calls** (`new GameObject(name, { position })`, `go.addComponent(Camera, { orthographic: true })`,
  `RenderSettings.skybox = { .. }`): stays as Rust lowering, but driven by record and property data from the manifest, so `split_rule`
  and the per-name special cases go.
- `Random.pick<T>`: a three-line intrinsic in the lowerer.

### Guard rails, from the first commit to the last

- **`iron-build check ../examples --tsc` green at every commit** (41 games; `M9-TS-2307` in `tools/iron_build/src/lib.rs` is the
  test form). A phase moves a declaration in one commit: add the native / generated form **and** delete the hand-written one, never one
  without the other.
- **No double declarations (M9-TS-3001):** while `engine_ts.d.ts` and `ambient.d.ts` still exist, a test fails if one of them declares a
  name or member that the manifests / builtins / UI tables now generate. Today `parse_supplement` silently lets the hand-written
  member win, and interfaces merge silently with generated classes, so drift would not show; this test makes the overlap an error.
- **API surface snapshot (M9-TS-3002):** a test parses the generated `iron.d.ts` with `oxc_parser` (`SourceType::d_ts()`; iron_ts already
  depends on oxc) and writes a normalised listing (one line per declared name / member with its type, comments and formatting dropped,
  members sorted) to `tools/iron_ts/tests/golden/api_surface.txt`; the test compares and `IRON_BLESS=1` rewrites. Taken **before phase 1**
  from today's output, so every later diff is reviewed as an intended API change ("generated d.ts equals today's declarations modulo
  formatting", with the deliberate differences visible in the diff). This file is generated data, not a declaration file.
- **`generated_dts_only` (M9-TS-3000):** walks the repository (skipping `target`, `node_modules`, `dist`, `types`, `.git`, `.claude`) and

  `.py` under `tools/iron_ts`. It starts as a **ratchet**: an allowlist (`engine_ts.d.ts`, `ambient.d.ts`, `facade.ts`, `gen_ambient.py`,
  and `js/react/src/react-refresh.d.ts` if question 7 says the rule covers `js/`) plus a maximum `//# when` chunk count (50), lowered by
  every phase; phase 5 empties the allowlist. A second check in the same test: every generated output carries the `// Generated by
  iron-build types` header.
- **No bun:** every test here runs with cargo (and `tsc` from `node_modules/.bin` or `PATH`, skipped with a message as `M9-TS-2307`
  does when missing). Numeric oracles are captured from the *current compiled facade* (run through `iron_ts` in a test before the chunk

## 5. Open questions for the user

1. **Raw TypeScript text next to Rust items.** Is `#[ts(type = "NumberList")]` on a Rust item (and a raw signature in a built-in table
   entry for `useCallback` / `useContext`) acceptable as "generated from Rust", or must every type be built with the typed builder?
2. **Compiler runtime written in TypeScript.** Does the rule also cover the compiler's own preludes that are compiled into games but are
   not engine logic (`temporal.ts` 1,690 lines, the `Error` / Intl / `Task` / timer classes in `prelude.rs`, `ui.ts`'s hook helpers)? This
   plan moves only the engine parts (`__win_pending`, the UI event slots, the style prelude).
3. **QuickJS wiring.** May the app's QuickJS runtime call `iron_native::install` now (docs/iron-api.md hand-over step 1)? It is the
   prerequisite for "one implementation for both". And is it acceptable that the QuickJS `SplineAnimate` stays a thin TS component over
   a native helper until QuickJS `GameObject`s are native?
4. **Saving the path.** Should `SplineAnimate.spline` (and a `Spline` as an inline asset, like `Material`) be saved in scene files now
   that it is native? `js/engine` does not save it; saving is new behaviour.
5. **API shape fixes.** Accept small changes where the native form is cleaner or the two copies disagree: `Shapes` as a namespace (call
   sites unchanged), `Spline.knots` a read-only snapshot, `AnimationCurve.fromPoints` typed `[number, number][]` instead of
   `number[][]`, `Assets.onChanged` called once per path, and `Gamepad.buttons` / `axes`: add them natively or drop them from the types?
6. **Enum wire form.** Strings (as today; QuickJS-friendly, a little slower) or numeric indexes with the literal union only in the
   types (faster compiled calls, a mapping in the QuickJS binding)?
7. **Scope of `generated_dts_only`.** Only `tools/` (the iron_ts toolchain), or the whole repo, including the legacy bun / QuickJS path
   (`js/react/src/react-refresh.d.ts`, the TS types inside `js/engine` and `js/react` that bun games still read)?
8. **Other generators in Python.** `crates/iron_render_api/gen/gen_components.py` writes `generated.rs` (6,461 lines). It generates Rust,
   not declarations, so it does not break the rule, but "no Python step" may still apply: replace it with a Rust build script or
   macro too (it would need new field types for this plan, e.g. nullable colour)?

## 6. Decisions (user, 2026-10-22)

1. Raw TypeScript text next to Rust items (`#[ts(type = "...")]`, raw signatures in the built-in table) counts as generated from Rust. The typed builder stays the default.
2. As much as possible is native Rust. The compiler's own TypeScript preludes (`temporal.ts`, the `Error` / Intl / `Task` / timer classes, `ui.ts` hook helpers) are in scope as a long-term goal, to be moved to Rust where practical, after the engine parts (phases P1 to P5). Nothing is promised for them in the first pass.
3. QuickJS calls `iron_native::install` now (prerequisite for one implementation for both). The QuickJS `SplineAnimate` may stay a thin TS component over a native helper until QuickJS GameObjects are native.
4. `SplineAnimate.spline` and a `Spline` as an inline asset are saved in scene files by the engine.
5. The small API shape fixes are accepted (`Shapes` as a namespace, `Spline.knots` a read-only snapshot, `AnimationCurve.fromPoints` typed `[number, number][]`, `Assets.onChanged` once per path). `Gamepad.buttons` / `axes` are added natively.
6. Enums travel as numeric indexes for speed (constant string literals are converted to indexes at compile time). Add converters in both directions: a native name-to-index and index-to-name pair per enum (for example `FogMode.name(i)` and `FogMode.parse("linear")`), usable from compiled code and QuickJS, so dynamic values can be converted.
7. `generated_dts_only` covers `tools/` only (the legacy bun / QuickJS path is out of its scope).
8. `gen_components.py` (Rust generation) is replaced later by a Rust build script or macro. Not part of the first pass.

## 7. Progress (2026-10-22)

**P0 done** (`tools/iron_build/tests/generated_dts.rs`): `M9-TS-3100` ratchet (hand-written `.d.ts` files, `include_str!` of them,
`facade.ts` chunks, Python under `tools/iron_ts`), `M9-TS-3101` no name declared by both the manifests and a hand-written file beyond
a listed set, `M9-TS-3102` API surface snapshot (`tests/golden/api_surface.txt`, `IRON_BLESS=1`). IDs used: `M9-TS-3100..3103`,
`3110..3116` and `M9-API-1600..1614` (another agent took `M9-TS-3000..3034`).

**P1 done**: `Shapes` (`iron_math::outlines`), `Spline` (`iron_math::spline`, `iron_engine_api::spline`) and `SplineAnimate` (a component
kind with scene-file save / load, the `Spline` inline asset, host `update`) are native; their facade chunks (3 of 50) and the
hand-written declarations (66 lines of `engine_ts.d.ts`) are deleted; the declarations are generated. QuickJS installs
`iron_native` (decision 3). Oracles are the old compiled TypeScript kept renamed in `tools/iron_ts_tests/bench/outlines.ts` (a
differential test, bit for bit, in every GC mode), instead of captured JSON. What the P1 extensions turned out to be:

- **F-ENUM**: `enums(TangentMode = Tangent [Auto, Bezier, Linear])` on the attribute; `i32` index on the wire; constant strings are
  folded at compile time, anything else goes through the generated `iron_<Enum>_parse`; results through `iron_<Enum>_name`;
  `TangentMode.name(i)` / `.parse(s)` exist as globals in both backends.
- **F-REC / F-LIST (results only)**: `records(..)` and `-> Vec<V | Record>` come back through a per-thread number buffer read with
  `iron_api_result(i)`; records as parameters are not built (P2b).
- **F-CTOR**: `#[options(after = p)]` (manifest `optionsAfter`; the constructor line `(points?, options?)`).
- **F-DOC**: module, class, function, enum, record and field docs reach the JSON and the `.d.ts`.
- **F-EXT not needed**: `SplineAnimate` is a handle class like `Camera` (no `extends Component`); `like` (value parameters
  as `Vector3Like`), `#[nullable]` (`T | null`) and `#[rest]` were added instead.
- **Not done**: F-UNION, F-NULL as a general `Option<T>`, records as parameters, F-SUB, F-PROMISE, F-JSON (P2 and later).

## 8. Progress, P4 (2026-10-22)

**Not done (P4b):** moving the hook helpers of `ui.ts` into Rust.
